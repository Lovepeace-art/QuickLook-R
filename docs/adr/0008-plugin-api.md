# ADR-0008：插件走进程内 C ABI（DLL 导出函数），不走进程外 JSON-RPC

- 状态：已采纳（M6 起头，0.5.0）
- 日期：2026-10-31
- 关联：`docs/dev/PLUGINS.md`、`crates/qlr-plugin-api/`、`crates/qlr-core/src/plugins.rs`

## 背景

用户要求：内置只留图片 / PDF / 文本 / Markdown 四类，**其余格式以插件形式单独开发并支持到项目里**
（原话见 `docs/dev/STATUS.md` §9）。所以必须有一套"第三方代码接入渲染管线"的机制。

WBS 的 A5 原本写的是"进程外 JSON-RPC 插件体系"（`docs/route-a-wbs.md` M5），那条路的好处是
崩溃隔离——插件挂了宿主不受影响。但它是给"25 个官方插件、每个都有独立进程、支持热重载"的规模设计的，
代价是：每个插件一个进程（内存 ×N）、要定协议版本、要处理进程启停与超时、要序列化位图
（一张 4K 图 33 MB，过 pipe 就是几毫秒 + 一次拷贝）。

而现在的真实规模是：**用户自己写几个补空缺格式的插件**，一个进程里跑得下，性能是首要诉求
（这正是整个重写项目的目标）。

## 决策

**选进程内 C ABI**，具体：

1. **插件 = 一个 DLL**，放在 `<exe>\plugins\*.dll`。导出三个符号：
   `qlr_plugin_info` / `qlr_plugin_render` / `qlr_plugin_free`。
2. **数据只过一次边界**：插件分配 RGBA 像素、宿主拷贝一份、插件立刻释放。
   不做共享内存、不做引用计数、不做零拷贝回调——那三种都要长期维护生命周期，得不偿失。
3. **契约单独成一个 crate `qlr-plugin-api`**，零依赖、纯 `#[repr(C)]`。
   宿主和插件引同一份定义，避免"两边各写一遍、字段顺序写错"这类经典事故。
4. **严格版本匹配**（`ABI_VERSION` 必须相等），不做兼容层。
5. **内置优先**：插件只能接管 `Kind::Unsupported` 的扩展名，不能覆盖四类内置格式。

## 为什么

- **性能**：视频首帧 2 ms、占比最大的成本是解码本身，进程内调用没有 IPC 开销（实测示例插件
  `PLUGIN … elapsed=2ms`，其中渲染 1.7 ms，跨界拷贝 3 MB 约 0.3 ms）。
- **体积**：`qlr-plugin-api` 零传递依赖，示例插件 DLL 只有 101 KB；宿主的 `libloading` 已经在
  用（PDFium 就是运行时加载的），**主 exe 一个字节都没涨**（1,732,096 B）。
- **可控**：插件能干的坏事被 ABI 限死了——只能返回一张图，拿不到 `HWND`、拿不到配置、
  拿不到文件句柄。像素上限 64 MP 硬挡"一个插件吃掉 4 GB"。
- **可测**：契约有结构体尺寸断言（`size_of::<QlrPluginInfo>() == 40`），一改就红。

## 备选与不选的理由

| 方案 | 为什么不选（v1） |
|---|---|
| 进程外 JSON-RPC（原 A5） | 每插件一个进程、位图要过 pipe 或共享内存；给"用户自己写几个插件"的规模上这套是过度工程。**保留为 v2 的方向**：`Kind::Unsupported` 那一层再包一个"进程外插件宿主"即可，ABI 不用动。 |
| WASM 沙箱（wasmtime） | 沙箱隔离最好，但 wasmtime 静态体积 10 MB+，直接违反 A8.5 的 exe ≤5 MB 预算。 |
| 脚本插件（Lua/JS） | 要嵌入解释器（+1–3 MB），且视频/Office 这类需求本来就要调原生库，脚本层只是加了一层胶水。 |
| 让插件覆盖内置格式 | 会让"内置行为"变成"装了什么插件就变什么样"，排障成本陡增；也给了插件抢 `.png` 这种热门扩展名的机会。**永不采纳。** |

## 后果（要接受的账）

- **崩溃即宿主崩溃**：插件里 `panic!` 或段错误会把 QLRust 一起带走。缓解：
  PLUGINS.md §4 要求"外部数据一律 `Result`"；宿主在 `load_plugin` 阶段就把缺符号/版本不符的插件挡掉。
- **只在启动时扫描**：装了新插件要重启（或改 `QLRUST_PLUGIN_DIR` 后重启）。
  v1 不做热重载——热重载要处理"旧 DLL 正在被调用时被删除"的 Windows 文件锁问题，收益不值这个复杂度。
- **插件拿到的是宿主的权限**：以同一用户身份运行，能读写任意文件。所以
  **只装你信任的插件**（PLUGINS.md §6 已写明；安装器不会去下载任何插件）。
- **位图只能静态展示**：v1 的返回值就是一张图，插件没法提供"播放/翻页"这类交互。
  音视频真要"能播"，v2 需要加一层"插件回调宿主重绘"的通道。

## 落地清单（本 ADR 对应的代码）

| 文件 | 角色 |
|---|---|
| `crates/qlr-plugin-api/src/lib.rs` | 契约：结构体、三个函数类型、符号名、扩展名归一化、尺寸断言 |
| `crates/qlr-core/src/plugins.rs` | 宿主：扫描目录、加载/校验、按扩展名查、渲染并拷贝、错误收集 |
| `crates/qlr-app/src/app.rs` | 派发：`render_with_plugin()`、`SHOW … plugin=` 日志、占位文字里的插件信息 |
| `crates/qlr-plugin-demo/src/lib.rs` | 示例插件（视频占位图），也是 PLUGINS.md 的模板来源 |
| `docs/dev/PLUGINS.md` | 给插件作者看的唯一入口 |
