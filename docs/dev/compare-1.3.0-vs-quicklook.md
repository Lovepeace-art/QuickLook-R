# QLRust 1.3.0 vs QuickLook 4.5.0：同机实测对比

> 机器：i5-12400F / 16 GB / Win10 22H2 19045 / x64，独显与集显都参与（QuickLook 会加载显卡驱动模块）。
> 时间：2026-11-01。脚本：`_bench/cmp-130.ps1`（结果 `_bench/cmp-130.json`）、`_bench/stress-*`、`_bench/verify-*.ps1`。
> 口径：**外部观测**——从 `CreateProcess` 到"窗口出现"，再到"窗口里有内容"（每 12 ms 用 BitBlt 抄一次窗口区域，
> 数偏离底色 >36 的像素，>400 判定为有内容）。两个引擎都是置顶无干扰窗口，尽量公平；
> 冷启动数字里包含 WMI 启动开销（约 15–25 ms）与采样粒度（12 ms）。

## 1. 冷启动到首帧（7 种文件）

| 文件 | QLRust 1.3.0 | QuickLook 4.5.0 | 倍数 |
|---|---|---|---|
| 4K JPEG（3840×2160） | **112 ms** | 1159 ms | 10.3× |
| 48MP JPEG（8000×6000） | **103 ms** | 1099 ms | 10.7× |
| 48MP PNG（8000×6000） | **99 ms** | 1071 ms | 10.8× |
| 16 MB 文本 | **104 ms** | 1463 ms | 14.1× |
| 8 页 PDF | **96 ms** | 1073 ms | 11.2× |
| 200 页 PDF（Word 转） | **87 ms** | 1060 ms | 12.2× |
| Markdown（27 KB） | **84 ms** | 1056 ms | 12.6× |

QLRust 内部里程碑（同一轮日志）：进程起 → 窗口创建 **8 ms** → 托盘/热键就绪 **11 ms** → 首帧渲染 2–30 ms。
也就是说外部测到的 ~100 ms 里，约 20 ms 是 WMI 启动、约 60 ms 是采样与抄屏开销。

## 2. 热启动（进程常驻，第二次打开同一个文件）

| 文件 | QLRust | QuickLook |
|---|---|---|
| 4K JPEG | 65 ms | **31 ms** |
| 48MP JPEG | 79 ms | **29 ms** |
| 48MP PNG | 71 ms | **21 ms** |
| 16 MB 文本 | 60 ms | **16 ms** |
| 8 页 PDF | 79 ms | **29 ms** |
| 200 页 PDF | 77 ms | **19 ms** |
| Markdown | 66 ms | **22 ms** |

**这一项 QuickLook 更快，是设计差异不是缺陷**：它把上一次的 WPF 可视树留在内存里，再打开只是"显示"；
我们每次打开都按当前窗口尺寸重新渲染（换来的是常驻 12–24 MB 而不是 170–400 MB）。
我们只在 PDF 上做了页缓存（翻页 0–2 ms），图片/文本没有缓存已渲染结果。

| 文件 | QLRust 常驻 | QLRust 峰值 | QuickLook 常驻 | QuickLook 峰值 |
|---|---|---|---|---|
| 4K JPEG | 13.2 / 3.9 MB | 12.4 MB | 222 / 256 MB | 137 MB |
| 48MP JPEG | 12.4 / 3.6 MB | 12.9 MB | **404 / 739 MB** | 150 MB |
| 48MP PNG | 12.2 / 3.3 MB | 11.5 MB | 405 / 742 MB | 137 MB |
| 16 MB 文本 | 23.7 / 13.7 MB | 38.9 MB | 222 / 189 MB | 138 MB |

| 200 页 PDF | 18.6 / 6.9 MB | 18.6 MB | 167 / 139 MB | 143 MB |

QuickLook 看 48MP 图时私有字节到 **739 MB**：WPF `BitmapSource`（8000×6000×4 = 192 MB）+ WIC 缓冲 + 渲染目标，
而且关掉预览后**不回落**（实测 162–414 MB）。QLRust 关掉就回到 13 MB。

GUI 资源（打开 4K 图时）：QLRust **GDI 20 / USER 16 / 句柄 153 / 7 线程**；
QuickLook **GDI 26 / USER 43 / 句柄 1219 / 26 线程**（200 页 PDF 时 40 线程、1238 句柄）。

## 5. PDF 翻页（我们自己的日志口径）

| 场景 | 耗时 |
|---|---|
| 页缓存命中（翻回去 / 预取过的下一页） | **0–2 ms** |
| 未缓存的新页（200 页 Word PDF，文本页） | 2 ms 渲染 + 0–2 ms 上屏 |
| 未缓存的新页（631×893，含图片的页） | 7 ms 渲染 |
| 2× 放大后重渲染 | 28 ms |

QuickLook 的页内翻页没法从外部稳定测量（没有 CLI，键位也不确定），这一项只给我们的数字。

## 6. 稳定性（我们的证据链，QuickLook 无法同样测）

| 项 | 结果 |
|---|---|
| 长稳压测 600 轮开关 + 150 次翻页 + 120 次缩放 | **7/7 PASS，56.2 s**：GDI 20→20、USER 16→16、句柄 153→153、私有字节 5.3→6.1 MB、重启后 12.9 MB 回到基线 |
| 更长一轮（2000 轮 / 500 翻页 / 300 缩放，1.2.0 时） | 7/7 PASS，166.8 s，同样零增长 |
| 渲染超时 | 超过 3 s 自动请求取消，窗口始终可关可换文件（实测卡死帧下关窗 123 ms） |
| 崩溃取证 | `crashes\` 下 `crash-*.txt` + `crash-*.dmp`（minidump 52–56 KB），下次启动提示"上次运行发生崩溃" |
| 畸形输入 | `malformed.rs` 7 组 + 确定性 fuzz，CI 每次 1 万例（`QLR_FUZZ_ITERS`），无挂起 |

## 7. 功能与生态（结构性差距）

| 维度 | QLRust 1.3.0 | QuickLook 4.5.0 |
|---|---|---|
| 内置格式 | **4 类 / 123 个扩展名**（图片、PDF、文本、源码、Markdown） | **25 个插件 / 308 个扩展名**（含视频、Office、压缩包、字体、3D、证书、邮件…） |
| 扩展机制 | 进程内 C ABI 插件（`qlrust_plugin_*`，示例插件 8 个扩展名）——**生态为零** | .NET 插件体系 + 官方/第三方插件仓库，用户量决定生态 |
| 视频/音频 | 无 | 有（LAVFilters + MediaInfo） |
| Office / 压缩包 | 无 | 有（走系统 IPreviewHandler） |
| 文本阅读 | 白底、行号、自动折行、滚动条、稀疏索引、源码高亮（仿 VSCode）、Markdown 真排版 + 目录 | 纯文本 / 简单富文本 |
| PDF | 页码框可输入跳转、页缓存 + 相邻页预取、缩小超采样、Shift 放大镜 | 基本翻页 + 缩放 |
| 窗口 | 无边框、黑顶栏（锁/↗/×）、柔和投影、拖边改大小、记住位置与尺寸、跟随选中项 | WPF 窗口，记住部分状态 |
| 系统集成 | 全局空格热键 + 托盘 + 每用户安装器（可选关联） | 全局热键 + 托盘 + **资源管理器右键菜单/预览窗格** + 商店分发 |
| 多语言 | 中文（配置位预留） | 多语言 |
| 体积/依赖 | 9.3 MB、0 个 .NET 依赖 | 278 MB、依赖 .NET Framework 4.6.2+ |

## 8. 结论

1. **冷启动 10–14 倍、内存在 1–30 倍（48MP 场景 60 倍私有字节）、体积 30 倍**——这是"原生 Rust + GDI"对"WPF + CLR + 25 个 .NET 插件"的结构性优势，不是调参能抹平的。
2. **热启动我们反而慢 2–4 倍**：QuickLook 留在内存里的可视树换来了这个，我们选择"每次重渲染、常驻 12 MB"。如果用户更在意热启动，最直接的补齐是"上一次的渲染结果留一帧"（内存 +2–4 MB，和预渲染同一套机制）。
3. **功能广度是真实差距**：视频、Office、压缩包、资源管理器集成、多语言、插件生态——这些是 QuickLook 十年的积累，我们只有 4 类格式的深水区。
4. **稳定性/可观测性我们更完整**：长稳压测、渲染看门狗、minidump、fuzz 都在 CI 里，QuickLook 没有对应的公开证据。

如果要继续投入，按性价比排序：
① 把"上一帧"也缓存起来（补热启动，成本最低）；
② 插件生态从"能跑"到"有人写"（文档 + 一个真插件：视频缩略图）；
③ Office/压缩包走"提取缩略图 + 文本大纲"的轻量路线，不做完整渲染；
④ 资源管理器集成（预览窗格 `IPreviewHandler`），这是我们和系统最缺的一环。
